Design rule

No rule is managed in two systems

Points, coupon and tier decisions live in the CRM; basket-level promotions, free shipping and gift rules on the platform. Which lives where is fixed in writing during discovery.

Overselling prevention

Under concurrent orders, campaign peaks and OMS delays the platform evaluates OMS available stock, reservations and pending orders together. Critical stock is closed on the channel through a fast lane.

Architecture principles

Composable, multi-tenant, extensible

MACH

Microservices · API-first · Cloud-native · Headless

Every capability is exposed through REST and GraphQL; presentation is fully decoupled from commerce logic. The Next.js WebShop and native iOS/Android apps consume the same API.

PBC

Packaged Business Capability

PIM, CMS, Payment, Campaign, CRM and Marketplace Seller are independently versioned packages with their own data and API. Changing one does not affect the others.

Multi-tenant

Two brands, one platform

Victoria's Secret and Bath & Body Works get separate sites, catalogs and designs; shared management, shared integrations, shared reporting. A new brand or country opens by configuration.

Extensible

Customisation without forking the core

Toggles, rule engine, user exits, scripting and plugin layers; Shaya-specific logic is added without leaving the upgrade path. No vendor lock-in, full export available.

EnginesRule · evaluation (best-choice) · action engines on the Microsoft Rules Engine; the same infrastructure for sourcing, campaigns, payment routing and content.
State machineOrder, payment, return and product lifecycles are modelled as valid transitions; every transition is validated against external systems and announced via webhook/event.

Confidential 14 / 34
Control Tower

Did the data arrive, is the work done: we see it before the customer

An integration running is not enough; its outcome must be right. Control Tower compares source and target, then prioritises and fixes the gap.

Product

Listing health

Products locked or rejected on the channel, or present in PIM but missing on the channel.

Inventory

Stock differences

Selling without stock, closed with stock, or showing more than the OMS.

Order & status

Order consistency

On channel but not in OMS, cancelled in OMS but open on channel, waiting too long.

Price

Price differences

Continuous comparison of the WinRetail price with the web, app and marketplace published price.

  • Prioritised by severity, fixed automatically. Fatal, critical and warning levels; every fix tracked as sent, fixed or failed, with history.
  • The checks themselves are monitored. A check that did not run or errored raises its own alert; "0 mismatches" never misleads.
  • Hourly digest and subscriptions. Operations is informed by e-mail; live stock and order lookup by barcode or order number on the same screen.

Failure scenarios

Confidential 18 / 34
Loading paths

Open API, Excel + mapping profile, ComHub transformation

Path 1 · Open API

Direct API loading

Product, category, attribute, customer and order endpoints; the Ticimax export is packaged to the source schema and sent in bulk. Each record returns a success/failure result with the reason.

Path 2 · Excel + mapping profile

What the operations team can do themselves

Download the template, upload the file, map the columns, review the plan, submit. The mapping profile is saved and reused next time. Row- and cell-level rule violation reports; nothing changes until submission is confirmed.

Path 3 · ComHub transformation

Transform on the way in

Source fields are transformed to the target model with scripts and lookups; unit, size and colour dictionaries are normalised. Delta transfers run on the same line, so only the difference moves on cutover night.

Selection rule: large, repetitive sets take Path 1 or 3; content and exceptions the brand team will correct take Path 2. All three pass the same validation rules and write to the same transaction history.
